# WealthCare 设计文档（Design）

> 版本：v2.0　|　最后更新：2026-07-28　|　配套文档：[需求文档](./需求文档.md)、[README](../README.md)

## 1. 架构总览

WealthCare 是一个 **Electron 桌面应用**，采用「主进程 + 渲染进程」经典双层结构：

```
┌─────────────────────────────────────────────────────────────┐
│  渲染进程（React + Vite，HashRouter）                          │
│  src/                                                         │
│   ├─ pages/      Dashboard / Assets / Liabilities / Analysis  │
│   │             Audit / Logs / Settings                       │
│   ├─ store/      wealthStore.ts（Zustand，业务状态 + 审计双写）│
│   ├─ types/      领域类型 + 汇总/显示名辅助函数                │
│   └─ vite-env.d.ts  window.electronAPI 统一类型声明            │
└───────────────┬─────────────────────────────────────────────┘
                │  preload.cjs（contextBridge，暴露 window.electronAPI）
                │  ipcRenderer.invoke('ns:method', ...)
┌───────────────▼─────────────────────────────────────────────┐
│  主进程（Electron，CommonJS）                                  │
│  electron/                                                    │
│   ├─ main.cjs      入口：初始化、注册 IPC、创建窗口            │
│   ├─ db.cjs        sql.js 内存 SQLite + 防抖写盘 + schema 迁移 │
│   ├─ logger.cjs     文件日志系统（查看/截断/归档/导出/轮转）   │
│   ├─ config.cjs     配置（dbPath / logDir）持久化              │
│   └─ preload.cjs    桥接层                                      │
└─────────────────────────────────────────────────────────────┘
```

**关键约束**：主进程开启 `contextIsolation: true`、`nodeIntegration: false`，渲染进程无法直接访问 Node，只能通过 `preload` 暴露的最小 API 调用系统能力。

## 4. 数据模型

### 4.1 数据库文件（默认 `userData/WealthCare.db`，sql.js 导出为单文件）

**`assets` / `liabilities` 表**（结构相同）
```sql
CREATE TABLE <t> (
  id          TEXT PRIMARY KEY,
  category    TEXT NOT NULL,
  data        TEXT NOT NULL,   -- 完整领域对象的 JSON
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
```
> 采用「宽表 + JSON 列」而非逐字段建列：资产/负债类别字段差异大，JSON 列简单且迁移成本低。

**`changes` 表（操作审计）**
```sql
CREATE TABLE changes (
  id          TEXT PRIMARY KEY,
  type        TEXT NOT NULL,      -- add | edit | delete
  target      TEXT NOT NULL,      -- asset | liability
  name        TEXT NOT NULL,
  category    TEXT NOT NULL,
  amount      REAL NOT NULL,
  timestamp   TEXT NOT NULL,
  summary     TEXT,               -- 变更摘要（如 "amount: 1000 → 1500"）
  before_data TEXT,               -- 变更前快照 JSON
  after_data  TEXT                -- 变更后快照 JSON
);
```
> `summary/before_data/after_data` 为后续增强列；旧库通过 `ALTER TABLE` 补齐（见 §5.2）。

### 4.2 配置（`userData/config.json`）
```json
{ "dbPath": "<默认或自定义 .db 路径>", "logDir": "<默认或自定义日志目录>" }
```

### 4.3 领域类型（`src/types/index.ts`）
- 资产：`BankDeposit | Securities | FundWealth | OtherAsset`（`AnyAsset` 联合）
- 负债：`Loan | CreditCard | OtherLiability`（`AnyLiability` 联合）
- 审计：`ChangeRecord { id, type, target, name, category, amount, timestamp, summary?, before?, after? }`
- 多币种：`currency: string` 已加入全部资产/负债接口；`ExchangeRates` 映射外币→CNY；辅助函数 `toRMB()`、`getAssetAmountInBase()`、`getLiabilityAmountInBase()`、`formatMoney()`。
- 辅助：`getAssetAmount` / `getLiabilityAmount`（汇总口径）、`getAssetDisplayName` / `getLiabilityDisplayName`。

## 5. 模块设计

### 5.1 主进程入口 `electron/main.cjs`
- 启动顺序（关键，避免递归）：`logger.init()` → `logger.captureConsole()` → `ensureDb()` → 注册 `db/config/logger` IPC → `createWindow()`。
- `window-all-closed`：非 macOS 时 `db.flushSave()` 后退出，确保防抖窗口内数据落盘。
- IPC 注册模式：`ipcMain.handle('ns:method', wrap(fn))`，`wrap` 内 `await ensureDb()` 后再执行。

### 5.2 数据库层 `electron/db.cjs`
- **内存库 + 防抖写盘**：`initSqlJs()` 加载 WASM；读已存在文件则 `new SQL.Database(buffer)`，否则新建；任何写操作后 `save()` 触发 300ms 防抖 `export()` 写文件；`flushSave()` 用于退出前立即落盘。
- **schema 修复 / 迁移**：
  - 缺失表则建表；表缺列则 `RENAME` 备份 → 重建 → 从 JSON 恢复 → 删备份。
  - `changes` 表存在时按 `ALTER TABLE` 补齐 `summary/before_data/after_data`（向前兼容旧库）。
  - 首次启动若当前路径无库，尝试从 legacy 路径（wealth-tracker / wealthcare 历史名）复制迁移。
- **审计查询**：`getAllChanges(options)` 支持 `type/target/category/keyword(fromDate/toDate)/limit/offset` 过滤；用 `SELECT ... before_data AS before, after_data AS after` 让 API 返回字段名与前端类型一致；`getChangesCount` 配合分页。

### 5.3 日志层 `electron/logger.cjs`
- **路径**：`getLogDir()` 每次从 `config.getLogDir()` 动态读取（支持切换即时生效）；归档目录为 `<logDir>/archive`。
- **写入**：`log()` 写内存 ring buffer（上限 500）+ 追加文件；写入前若文件 >5MB 触发 `rotateFile()`（复制归档并清空）。
- **自污染防护**：`logMemoryOnly()` 仅写内存不落文件，用于截断/轮转/切换目录等「操作日志文件本身」的动作，避免把截断标记又写回被操作文件。
- **console 接管**：`captureConsole()` 包裹 `log/warn/error`，并监听 `uncaughtException`/`unhandledRejection`，统一按 `[时间][级别][来源] 消息` 格式落盘。
- **读取/维护**：`readLog`（行数/级别/关键字/source 过滤）、`truncateLog`（保留最近 N 行 + 截断标记）、`archiveLog`/`archiveAllLogs`（复制到 archive，带时间戳）、`extractLog`/`extractLogsAsBundle`（导出单文件/汇总）、`reloadLogDir`（切换目录后重置路径缓存并建目录）。

### 5.4 配置层 `electron/config.cjs`
- 单例 JSON（`userData/config.json`），提供 `getDbPath/setDbPath/getLogDir/setLogDir` 及默认值、选择对话框（文件夹/数据库文件/日志文件夹）。
- 切换 `dbPath` 由 main 联动 `db.reloadDb()`；切换 `logDir` 由 main 联动 `logger.reloadLogDir()`。
- **汇率配置**：渲染层通过 `wealthStore.exchangeRates` 维护。Electron 模式下通过 `config:getExchangeRates`/`config:setExchangeRates` IPC 持久化到 `config.json`（与数据库同处 `userData`，重装/换机迁移一致）；浏览器模式下持久化到 `localStorage`（`wealthcare_exchange_rates`）。默认值由 `DEFAULT_EXCHANGE_RATES` 兜底，缺失字段自动合并。

### 5.5 渲染层
- **Store 双写（`wealthStore.ts`）**：6 个增删改方法在写入 DB 前调用 `writeAudit()` 同时写入 `changes` 表与 `audit` 来源文件日志；`getSummary()` 统一按人民币折算资产/负债金额。
  - `buildAuditSummary()` 生成人类可读摘要；`diffSummary()` 对比 `AUDIT_FIELDS` 关注字段，输出 `字段: 旧 → 新`。
  - 浏览器模式（无 `window.electronAPI`）回退到 `localStorage`，审计仅在内存保留最近 200 条。
- **页面**：Dashboard（指标卡 + 占比）、Assets/Liabilities（CRUD）、Analysis（recharts 饼图 + 按月组合图 + 打印）、Audit（筛选 + 分页 + before/after 展开）、Logs（文件列表 + 实时 + 过滤 + 截断/归档/导出）、Settings（DB/日志目录配置）。
- **类型**：`src/vite-env.d.ts` 统一声明 `ElectronAPI`（db/config/logger）及 `LoggerReadOptions`、`ChangeQueryOptions` 等，各文件不再重复声明。

### 5.6 IPC 契约一览

| 命名空间 | 处理器 | 用途 |
| --- | --- | --- |
| `db` | `getAllAssets/addAsset/updateAsset/deleteAsset` | 资产 CRUD |
| `db` | `getAllLiabilities/addLiability/updateLiability/deleteLiability` | 负债 CRUD |
| `db` | `getAllChanges/getChangesCount/addChange` | 操作审计读取/写入 |
| `db` | `migrate/importDbFile/backupDb` | 迁移/导入/备份 |
| `config` | `getDbPath/setDbPath/getDefaultDbPath/selectFolder/selectDbFile` | 数据库位置 |
| `config` | `getLogDir/setLogDir/getDefaultLogDir/selectLogFolder` | 日志目录 |
| `logger` | `listLogs/getRecentLogs/readLog` | 列表/实时/读取 |
| `logger` | `truncateLog/archiveLog/archiveAllLogs` | 截断/归档 |
| `logger` | `extractLog/extractLogsAsBundle/selectSavePath` | 导出 |
| `logger` | `getLogDir/write` | 目录查询/前端主动记录 |

## 6. 关键流程

### 6.1 启动流程
1. `app.whenReady` → `logger.init()`（建立目录缓存）。
2. `logger.captureConsole()` 接管 console（最早，捕获后续所有输出）。
3. `ensureDb()` 加载/迁移 SQLite。
4. 注册 db/config/logger IPC。
5. `createWindow()`，渲染进程 `useWealthStore.init()` 从 SQLite 加载数据，并尝试把浏览器模式的 localStorage 数据迁移进库。

### 6.2 操作审计双写流程（以修改资产为例）
```
UI 提交
  → store.updateAsset(id, updates)
  → writeAudit({ type:'edit', before: existing, after: updated })
       ├─ buildAuditSummary() 生成 summary
       ├─ db.addChange(change)          写 changes 表
       └─ logger.write('info','audit', 修改 资产「名」 ¥x | 变更: ...)
  → db.updateAsset(id, updated)         更新 assets 表
  → set() 更新内存状态
```

### 6.3 配置切换流程
- 切换 DB：`config.setDbPath` → main `dbReady=null; db.reloadDb()` → store `reload()`。
- 切换日志目录：`config.setLogDir` → main `logger.reloadLogDir()`（重置路径缓存、建目录）。

### 6.4 防抖写盘与退出保护
- 每次 DB 写操作后 300ms 内无新写则 `export()` 落盘。
- 应用退出（`window-all-closed`）前调用 `db.flushSave()` 强制立即落盘。

## 7. 安全与边界处理

- **隔离**：`contextIsolation: true`、`nodeIntegration: false`；仅 `preload` 经 `contextBridge` 暴露必要方法。
- **日志自污染防护**：截断/轮转/切换目录动作只写内存 ring buffer（`logMemoryOnly`），不写回正在操作的文件。
- **写盘失败不抛**：日志写入异常走 `process.stderr`，避免递归抛错死循环。
- **外部文件对话框**：导出/选择均经 Electron `dialog`，不暴露任意路径写权限到渲染层。
