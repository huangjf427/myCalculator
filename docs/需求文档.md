# WealthCare 需求文档（Requirements）

> 版本：v2.0　|　最后更新：2026-07-28　|　配套文档：[设计文档](./设计文档.md)、[README](../README.md)

## 1. 产品概述

| 项 | 内容 |
| --- | --- |
| 产品名 | WealthCare（财富管家） |
| 形态 | 本地桌面应用（Electron，Windows x64） |
| 定位 | 个人隐私财产管理工具，离线、单机、数据不出本机 |
| 目标用户 | 需要统一管理银行存款、证券投资、理财基金与负债的个人，支持多币种资产/负债统一折算为人民币 |
| 核心价值 | 一处记账、多币种净资产视图、可追溯的操作审计与运行日志 |

### 1.1 设计原则
- **本地优先**：所有数据存于本机 SQLite 文件，不依赖任何云端账户或网络。
- **可审计**：对资产/负债的每一次增、删、改都留下可追溯记录（类型、前后快照、摘要、时间）。
- **可运维**：独立文件系统记录运行日志，支持查看、过滤、截断、归档、导出。
- **可配置**：数据库文件位置与日志目录均可由用户在设置中切换。

## 2. 功能需求

### 2.1 资产管理（FR-1）
支持 4 类资产的增、删、改、查与列表展示：

| 类别 | 关键字段 |
| --- | --- |
| 银行存款 `bank_deposit` | 银行名称、户名、定/活期、币种、金额、存入日期、期限、利率、到期日/到期金额 |
| 证券投资 `securities` | 机构、户名、币种、本金、现值、收益 |
| 理财基金 `fund_wealth` | 机构、户名、币种、产品名称、本金、购买日期、期限、收益、到期日、现值 |
| 其他资产 `other_asset` | 资产名称、户名、币种、产品名称、本金、期限、收益、到期日、现值 |

- 金额汇总口径：银行存款取 `amount`；证券/理财/其他资产取 `currentValue`。
- 必填项（名称、金额/本金、金额类字段）在表单提交时校验。

### 2.2 负债管理（FR-2）
支持 3 类负债的增、删、改、查：

| 类别 | 关键字段 |
| --- | --- |
| 贷款 `loan` | 贷款名称、户名、币种、金额、开始日期、负债金额、利率、预期还款日、是否分期/每期额 |
| 信用卡 `credit_card` | 发卡机构、户名、币种、金额、利率、到期还款日 |
| 其他负债 `other_liability` | 同贷款结构 |

- 金额汇总口径：贷款/其他负债取 `liabilityAmount`；信用卡取 `amount`。

### 2.3 仪表盘（FR-3）
- 展示指标卡片：**总资产、总负债、净资产、负债率**。
- 展示资产与负债的**分类占比**（银行存款/证券/理财/其他；贷款/信用卡/其他）。
- 提供快捷入口跳转到资产/负债/分析页。

### 2.4 统计分析（FR-4）
- 资产构成饼图、负债构成饼图。
- 按月分布的资产/负债组合图（资产按到期日 `maturityDate` 归集；负债按还款/到期日归集），用于现金流/到期视图。
- 支持打印当前分析视图。

### 2.5 操作审计（FR-5）
记录对资产与负债的**新增 / 修改 / 删除**操作，供用户追溯。

| 字段 | 说明 |
| --- | --- |
| `type` | `add` / `edit` / `delete` |
| `target` | `asset` / `liability` |
| `name` | 对象显示名（如银行名、产品名、贷款名） |
| `category` | 资产/负债类别 |
| `amount` | 操作涉及金额（汇总口径） |
| `timestamp` | ISO 时间 |
| `summary` | 人类可读摘要，如「修改资产「ICBC」¥1500.00（amount: 1000 → 1500）」 |
| `before` / `after` | 变更前/后完整对象快照（JSON） |

功能要求：
- 查看：列表按时间倒序，分页（每页 50 条）。
- 筛选：按操作类型、对象（资产/负债）、类别、日期区间、关键字（名称或摘要）。
- 详情：可展开行查看 `before` / `after` 的 JSON 对比。
- 审计日志本身支持在其来源（system logs 的 `audit` 来源）下查看、截断、归档（见 FR-6）。

**验收标准**：新增一条资产后，审计页出现一条 `add` 记录且 `after` 含完整数据；修改金额后 `summary` 显示字段变化（如 `amount: 1000 → 1500`），`before`/`after` 可对比；删除后 `before` 含被删对象快照。

### 2.6 系统日志（FR-6）
独立于数据库的文件日志系统，记录应用运行与操作审计。

- **存储**：按日期分文件（`app-YYYY-MM-DD.log`），位于可配置日志目录；归档文件置于该目录下 `archive/` 子目录。
- **内存缓冲**：最近 500 条 ring buffer，供「今日实时」视图展示。
- **级别**：`INFO` / `WARN` / `ERROR`，行格式 `[时间] [级别] [来源] 消息`。
- **来源标签**：`console`、`main`、`db`、`logger`、`audit`、`process`（异常）。
- **自动轮转**：单文件超过 5MB 自动复制归档并清空原文件。
- **console 接管**：`console.log/warn/error` 与未捕获异常/未处理 Promise 拒绝均落盘。
- 查看能力：
  - 左侧文件列表 + 「今日实时」内存视图。
  - 级别过滤（INFO 及以上 / WARN 及以上 / 仅 ERROR）、来源过滤（含「只看 audit」）、关键字搜索、行数选择（200/500/1000/5000）。
  - 行级着色（ERROR 红、WARN 琥珀、INFO 绿）。
- 维护能力：
  - **截断**：保留最近 N 行，删除前面内容（操作含确认与行数输入）。
  - **归档**：复制单文件或全部文件到 `archive/`（带时间戳），原文件保留。
  - **导出**：导出单个日志到指定位置，或将全部日志合并为单个汇总文件导出。
- **自污染防护**：修改日志文件本身的操作（截断、轮转、切换目录）只写入内存，不写回正在操作的文件。

**验收标准**：触发任意操作后在「今日实时」可见对应来源日志；截断后文件仅保留指定行数且保留行未被截断标记污染；归档后在 archive 目录出现带时间戳副本；导出可得到目标文件。

### 2.7 设置（FR-7）
- **数据库位置**：显示当前路径、选择新位置（切换后立即 reload 新库）、恢复默认、导入外部 `.db` 文件（导入前自动备份）、手动备份当前库。
- **日志目录**：显示当前目录、选择新位置（切换后新日志写入新目录，已存在文件不自动迁移）、恢复默认。
- **汇率设置**：维护各外币到人民币（CNY）的汇率；支持恢复默认值。

**验收标准**：切换数据库位置后应用加载新位置数据；切换日志目录后新日志落在新目录；恢复默认后回落到 `userData/logs`；修改汇率后汇总数值即时刷新。

### 2.8 多币种支持（FR-8）
- 所有资产/负债均支持 `currency` 字段，默认 `CNY`。
- 支持币种集合由 `SUPPORTED_CURRENCIES` 定义（至少 CNY/USD/EUR/HKD/JPY/GBP）。
- 汇率在「设置」中维护；外币金额按汇率折算为人民币后参与汇总。
- 汇总口径：资产统一按人民币折算（`amount * exchangeRate`）；负债同样折算为人民币。
- 展示规则：明细列表显示原币种金额；仪表盘、资产/负债总览、统计分析、打印表均显示折算后的人民币金额。
- 历史数据兼容性：缺少 `currency` 字段的旧数据默认视为 `CNY`；缺少汇率配置时使用 `DEFAULT_EXCHANGE_RATES` 兜底。

**验收标准**：新增一笔 USD 资产后，仪表盘总资产按 USD→CNY 汇率折算；修改汇率后所有汇总即时更新；旧版数据库打开后汇总数值不变。

## 3. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 平台 | Windows 10/11 x64；通过 electron-builder 产出 NSIS 安装包与便携版 |
| 离线 | 无任何网络依赖，所有数据本地存储 |
| 安全 | 主进程开启 `contextIsolation`，关闭 `nodeIntegration`；渲染进程仅经 preload 暴露的最小 API 访问系统能力；日志/数据均不对外传输 |
| 性能 | 数据库写盘采用 300ms 防抖，避免频繁 I/O；审计查询在数据库层分页，渲染层仅加载当前页 |
| 兼容性 | 旧版本数据库/旧 schema 自动迁移：legacy 路径复制、缺列用 `ALTER TABLE` 补齐、changes 表向前兼容 |
| 可维护性 | 类型集中在 `src/types`，Electron API 类型统一声明于 `src/vite-env.d.ts`；主进程按职责拆分为 `db/logger/config` 模块 |
| 数据持久化 | 应用退出前 `flushSave()` 立即落盘，避免防抖窗口内数据丢失 |
| 可观测性 | 运行日志 + 操作审计双轨，便于排障与问责 |

## 4. 数据需求

### 4.1 持久化范围
- 资产、负债：SQLite `assets` / `liabilities` 表，每行 `data` 列存完整 JSON 对象 + `category`/`created_at`/`updated_at`。
- 操作审计：`changes` 表（`id, type, target, name, category, amount, timestamp, summary, before_data, after_data`）。
- 配置：`userData/config.json`（含 `dbPath`、`logDir`）。
- 运行日志：独立 `.log` 文件系列（不进数据库）。

### 4.2 生命周期
- 审计记录：仅追加，由 store 在增删改时**双写**（同时写 `changes` 表与 `audit` 来源文件日志）。
- 日志轮转/截断/归档对原始审计语义无损（归档为复制，截断仅针对运行日志文本）。

## 5. 用户场景（示例）

1. **日常记账**：用户新增一笔定期存款 → 仪表盘总资产上升 → 审计页出现 `add` 记录。
2. **纠错**：用户发现某证券现值填错 → 修改 → 审计页出现 `edit` 记录，`summary` 显示 `currentValue: x → y`，可展开对比 before/after。
3. **排障**：应用异常 → 开发/运维打开系统日志「今日实时」按 ERROR 过滤定位，必要时截断归档后导出给支持人员。
4. **换机/备份**：用户在设置中备份数据库；或导入旧机导出的 `.db` 恢复全部数据（含审计）。
5. **外币记账**：用户新增一笔美元证券投资，设置 USD→CNY 汇率，仪表盘与分析页统一按人民币展示总资产。修改汇率后净资产即时重算。
